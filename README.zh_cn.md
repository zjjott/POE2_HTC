# POE2 制作指南

英文说明：[README.md](README.md)

一个算出**流放之路 2 里这件装备该怎么做、要花多少**的网页工具。它用精确的概率，而不是抽样，在真实的 0.5.0 词缀池上计算；每天用一份 poe.ninja 价格表给每条路线标价，并展示最便宜和最稳妥之间的取舍。制作计算全部在浏览器里完成，不用安装。

界面可以在页眉切换 **English / 简体中文**。简体用于国服用词：词缀句子、阶位名和底子名来自 [poe2db 简体页](https://poe2db.tw/cn/Amulets)，按词缀 id 叠在英文数据上。求解、分享链接里的 id 不变。缺译文的地方仍显示英文。

**现在就用：[poe2htc.com](https://poe2htc.com)** · **[Discord](https://discord.gg/RvxCWyFF3D)**

## 功能

- **按最优打法算期望花费。** 一般计算器给的是固定配方：这五步，第三步失败就重来。实际制作不是这样——掷歪了，你会看手里这件再决定下一步。引擎把这件事做成马尔可夫决策过程，报出来的是打得好、就地补救的花费，不是每次都重开的花费。
- **最优制作路径。** 给出到达你要的词缀和阶位的通货顺序、每一步的精确概率，并与 Craft of Exile 和蒙特卡洛模拟对照过。
- **花费与成功率的取舍。** 一组帕累托方案，从最便宜到最稳妥，价格用 [poe.ninja](https://poe.ninja) 的崇高石等价。
- **从买来的物品接着做。** 从零做的同时，列出已经带上部分目标词缀的物品、从每一件收尾要多少、值得出多少钱。填上你看到的交易价格，它会标出最值得买的那件，并画出从它出发的路线。
- **主播装备。** 浏览主播角色上的真实终局装备，交给规划器：从零做、从你手里的物品瞄准它，或把它当作你已经有的物品。
- **我已经有这件。** 填上物品当前的词缀，从这一步给出最好的下一步，而不是从白板开始。
- **真正用得上的通货。** 基础、高阶、完美的各种石，精华和完美精华，渎灵（含远古骨）和深渊回响的预兆，其他预兆，破裂词缀。
- **预算模式。** 说出你能花多少，得到这笔钱实际上能做完的最接近的物品，以及在预算内做完的概率。
- **排除通货。** 没有完美崇高，或者不用预兆？勾掉它们，规划会绕开。
- **分享一套制作。** 复制链接会在别人的浏览器里还原底子、词缀、阶位和预算。你自己的工作区在访问之间会保留。对方看到的语言是他自己选的，链接里不带语言。
- **搜索力度。** 快速、标准或彻底。大制作算不稳时，页面会说明，并可以一键提高一档再算。
- **在浏览器里运行。** 每次求解都在 Web Worker 里、在你这台机器上。离开页面的只有匿名访问计数、应用出错时的错误报告（带这次会话的回放，方便复现），以及你选择发送的评分。
- **给应用评分。** 星级和几句话，直接到维护者，不用邮箱，不用账号。

## 快速开始

打开 [poe2htc.com](https://poe2htc.com)。桌面和手机浏览器都可以。

第一次用，看 [用户指南](docs/USER_GUIDE.md)（英文）。用过的话，[1.0 的变化](docs/WHATS-NEW.md)（英文）介绍站点现在做什么。

页眉的语言菜单选 **简体中文**。词缀列表、阶位名、底子类别和页眉、规划页上的主要按钮会换成简体。说明长文仍是英文。把国服物品用 Ctrl+C 粘进来时，会先按简体词条对上同一条英文 id，再交给原来的求解。

### 从源码运行

需要 Node.js 20+（不用 Java，不用数据库）。

```bash
git clone https://github.com/Dboire9/POE2_HTC.git
cd POE2_HTC
npm install      # .npmrc 已设置 legacy-peer-deps，React 19 需要它

npm run dev      # 开发服务器 http://localhost:5173
npm run build    # 或把静态站点构建到 dist/
```

本地除了 **给应用评分** 都能用。评分会发给一个 Vercel 函数，`npm run dev` 不提供它。

简体词条表在 `data/patches/0.5.0/locale/zh-CN.json`。游戏数据更新后，用下面的命令从 poe2db 的 `/cn/` 页重新生成（会联网，结果缓存在 `tools/refresh/cache/poe2db/cn/`）：

```bash
node tools/refresh/apply_locale.mjs
```

## 它怎么工作

三条入口，看你从哪里开始。

**从白板开始** —「从零规划」：

1. 选择底子、物品等级，以及要的词缀和阶位
2. 计算。引擎用词缀池权重做精确概率
3. 查看帕累托前沿：从最便宜到最可能成功，每条都有分步说明和每步概率；另外给出打得好时的真实期望花费，以及与其买白板不如买哪件半成品
4. 在游戏里按通货顺序做

**从手里的物品开始** —「我已有物品」：填上已经有的词缀，说你希望它做成什么样。引擎从当前状态回答，并会告诉你最好继续，还是该停。

**从别人的物品开始** —「主播装备」：选一件主播真正做出来的物品，送到上面两个标签之一。装备是带日期的快照，带不过来的词缀会逐条写明。

引擎考虑稀有度变化、词缀权重、通货行为和强度（基础 / 高阶 / 完美）、预兆、词缀族冲突、物品等级门槛、破裂词缀和孔位上限。蒙特卡洛只用来**核对**解析结果，不产生你看到的数字。

### 两个求解器，两个问题

每次制作都会跑两个求解器，因为它们回答的不是同一个问题。

**步骤规划器**给出**帕累托前沿**：不存在另一条又更便宜、又更可能成功的方案。每条方案是固定的通货序列，概率在每一步的词缀权重池上**解析**算出来，不是抽样。它回答的是「配方是什么，每次尝试的概率是多少」。

**策略求解器**把制作建成马尔可夫决策过程——每个能到达的物品状态、从那里能走的每一步——用策略迭代求**真实期望花费**：每一次掷完，无论好坏，都从你实际所在的状态选最好的下一步，这套制作要花多少。它回答的是「这真正会花掉我多少」。这个数几乎总是低于前沿上的数字，因为前沿只能重来，而真正的制作会补救。

要点：

- 每一步和整条方案的概率是精确的，没有抽样噪声
- 花费用每天刷新的 poe.ninja 价格表，单位是崇高石等价，方案可以按钱排序
- 覆盖流放之路 2 的规则：稀有度变化、石的强度、预兆、精华、渎灵、词缀族互斥、物品等级门槛、通货阶位下限、破裂词缀
- 算不完就老实说：页面打出「≥ x」或「≤ x」，而不是一个装确定的数
- 在本地 Web Worker 里跑。求解过程不联网，可以取消，有进度条

面板和每个数字的说明见 [用户指南](docs/USER_GUIDE.md)。数学见 [算法说明](docs/ALGORITHM.md)。两份都是英文。

## 开发

- **应用**：React 19 + TypeScript + Vite，静态站点。界面在 `src/features/`，由 `src/lib/engine.ts` 驱动
- **引擎**：`packages/engine`，纯 TypeScript 制作引擎（无 I/O、无 DOM），按通货做精确的权重池概率
- **优化器**：`packages/optimizer`，帕累托前沿、从已有物品规划，以及 MDP 策略求解，带蒙特卡洛自检
- **数据**：`data/patches/<patch>/*.json`，分版本的词缀、底子和价格（应用带的是 `0.5.0`）。`data/patches/0.5.0/locale/zh-CN.json` 是简体显示层。`data/streamers/` 是主播装备快照
- **语言**：`src/lib/i18n.ts` 是界面文案；`src/lib/lexicon.ts` 是词缀、阶位和底子名。默认英文，所以现有测试看到的仍是英文
- **服务器**：`api/feedback.ts` 是唯一的服务端函数，即「给应用评分」，跑在 Vercel 上，前面有 BotID。除此之外没有服务器
- **自动化**：GitHub 工作流每天从 poe.ninja 刷新价格表，市场数据通过流动性检查后自己合并 pull request

CI 在每次推送时跑：

```bash
npm test -- --run
npm run type-check && npm run type-check:engine && npm run type-check:optimizer
npm run lint
npm run build && npm run test:e2e
```

搭建和贡献见 [开发指南](docs/DEVELOPMENT.md) 和 [贡献指南](docs/CONTRIBUTING.md)（英文）。

## 已知限制

这些是真实的界限。它们不会让屏幕上的数字在该精确的时候变成错的——引擎不确定时会在页面上说明。

- **渎灵词缀的出现权重是测出来的，不是官方公布的。** poe2db 给每条渎灵词缀的权重都是 1，这不可能对。随包的 2500 来自在一个底子上用 40 次骨的样本：够用，但还不能确定它不随物品类别变化。不用首领预兆的渎灵会在应用里标明，并把那些概率标成估计；其余概率是精确的。
- **步骤规划器不会垫垃圾词缀。** 它写出的每一步都指向一条目标词缀，所以表达不了「先掷一条垃圾、洗掉，再渎灵」这种游戏里可行的路线。策略求解器可以找到这类路线，这也是两个模型数字不同的原因之一。
- **护符和珠宝不支持。** 它们和普通装备的分类不同（护符在游戏数据里是药剂，珠宝有自己的词缀模型），放不进这个优化器规划的 3 前缀 / 3 后缀稀有装。其余装备位都支持。
- **大制作要有耐心。** 六条顶级词缀可能要用「彻底」搜索力度，算几分钟；在此之前页面给出的是界限，不是猜测。

`docs/copy-audit.md` 列了应用声称的每一件事，以及实际由什么保证。已报告的问题见 [Issues](https://github.com/Dboire9/POE2_HTC/issues)。
